# One-time 1 SKR video pilot

This is an isolated pilot branch, **not** the daily free rehearsal release. The game still calculates each majority from blind votes on the server. One funded Mainnet prize wallet pays **exactly 1 SKR only if the round has one sole finalist**. An operator must explicitly announce the pilot and start the local payout watcher for that round. The watcher sends after the final result and verifies the transfer on-chain. It is not escrowed or a general-purpose payout service. Any scripted participants must be labeled as simulated in the video.

The official [Solana Mobile SKR address](https://solanamobile.com/skr) is `SKRbvo6Gf7GondiT3BbTfuRDPqLWei4j2Qy2NPGZhW3`. The payout tool checks the Mainnet genesis hash, that mint's Token Program owner and six decimals before preparing a transfer. It transfers to the sole finalist's standard associated token account, creating that account if needed. The recipient does not need to pay a fee.

## Pilot setup and recording

1. Apply `supabase/migrations/202610090001_skr_pilot.sql`, then deploy the pilot branch's `game` Edge Function. The migration adds a private, one-time pilot record. No scheduled daily rehearsal receives a prize automatically.
2. Build and install the pilot APK on the Seeker. The normal APK remains the free-rehearsal version. Schedule a future ten-question, zero-SOL round for the video. Use several distinct test wallets and openly identify scripted players as simulated. Arrange their answers so the Seeker is the sole finalist.
   For a supervised two-opponent scene, run `node scripts/rehearsal-player.cjs ROUND_UUID support` and `node scripts/rehearsal-player.cjs ROUND_UUID dissent` in separate terminals before the round starts. The support player votes A on questions 1–9 and abstains on question 10; the dissent player votes B on question 1 and then abstains. The Seeker player can vote A throughout. These are deliberately simulated votes, not evidence of organic audience size, and an unexpected real player can change the majority. Use a dedicated video round rather than a scheduled daily round so its sentiment recap stays honest.
3. Set `HUNDO_SKR_TREASURY_DIR` to the private treasury directory, `HUNDO_SUPABASE_URL` to the project URL, and `HUNDO_SUPABASE_SERVICE_ROLE_KEY` to the service-role key in a private local environment. Never put the service-role key in an app bundle, GitHub, a shell command recorded in the video, or this document.
4. After funding, run `node scripts/skr-pilot-payout.cjs status`, then `announce ROUND_UUID` **before** the round starts. Announce checks that the prize wallet is funded and registers the one-time pilot; the app then shows 1 SKR and the public treasury address.
5. Before gameplay, start `node scripts/skr-pilot-payout.cjs auto ROUND_UUID` in a terminal that remains running on this Mac. It is restricted to the confirmed pilot recipient `GhSaDCrTNbXwLWPXzzEVqWYVwMfNocUMqNG3BTkzDU9Z`. It waits until the final screen, checks that this wallet is the sole finalist, prepares exactly 1 SKR, broadcasts the saved transaction, and waits for finalization. If someone else wins or there is a tie, it stops without payment. Starting the watcher does not start the game.
6. Record Seeker gameplay and the result. Keep the computer awake and connected. The app displays the Mainnet transaction link after the payout is finalized and verified. Network finalization and public RPC responses can take longer than the first broadcast, so do not promise an exact number of seconds on camera. If the watcher stops, inspect its error and the saved receipt before any retry. The manual `prepare ROUND_UUID WINNER_WALLET`, `send ROUND_UUID`, and `verify ROUND_UUID` commands remain available for recovery; `send` always reuses the same signed transaction.
7. Record the Explorer transaction and the winner's wallet balance. Once the video is captured, stop using the pilot build and return to the normal test APK. Keep the signed receipt and wallet backup for audit; do not imply recurring paid games are live.

The payout watcher is intentionally started by an operator for one named round on this Mac. It does not hold a permanent server signing key, pay ties or non-finalists, or retry with a fresh transaction automatically after blockhash expiry. A production prize system still needs an audited payout executor, funding controls, monitoring, anti-bot rules, and independently verified scale tests.
